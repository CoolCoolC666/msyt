# 样例词表（关键词设计）

> 依据：《网络舆情搜集》方法课第三张课件「建立『词表』，关键词设计」。
> 本文件说明**口径与取舍**；**词表本体在 `样例词表.csv`**（唯一事实源）。
> 词表在系统里的落地形态：`keywords` 表 + `keyword_hits` 命中台账 → 界面「词表」页签 → 导出 CSV 的「词表命中」列。

---

## 一、为什么要做词表

课件把「词表」列为核心词、主体词、事件/问题词、扩展词、排除词五类，并给了一条硬要求：
**排除词是"减"的，不是"加"的** —— 命中排除词的样本，要从其它词的命中里**扣掉**。

我们此前**全库零关键词召回**：站内检索走 SQLite FTS 的 trigram 分词器，
**2 字中文词（地铁 / 公交 / 垃圾 / 道路…）命中恒为 0**，3 字词才 100% 命中；
20 个词合计覆盖率仅约五分之一（详见《网站优化报告》实测）。

词表顺带把这个坑解掉了：**词表扫描不走 FTS**，而是一次全表扫描 + 多词判定（`content.count(word)`），
所以 **2 字词照样能命中**。

## 二、五类词怎么分的（口径）

| 词类 | 作用 | 本样例的口径 |
|---|---|---|
| **核心词** | 研究对象本身 | 平台名与热线号：`民生e点通`、`12345` |
| **主体词** | 诉求涉及的**公共对象/设施** | 道路、停车、公交、学校、地铁、垃圾、医院、路灯、菜场、河道、井盖、供电、燃气、供水 |
| **事件/问题词** | 诉求的**问题类型** | 施工、安全隐患、收费、噪音、污染、占道、漏水、积水、堵车、换乘、异味、无法通行、晚点、停电 |
| **扩展词** | 同一对象的**别称/写法变体** | 轨道交通→地铁、公交车→公交、断电→供电、停水→供水、道路破损→道路、垃圾箱→垃圾、异味扰民→异味 |
| **排除词** | 命中即**扣掉**该样本 | 广告、招聘、转载 |

**选词依据不是拍脑袋**：每个候选词都先在真库上跑过词频审计
（`_tools/audit_word_counts.py`，命中量随库变化，属活口径），
只从「在真实语料里确实出现、且量级够用」的词里挑。

**扩展词用 `parent` 指回主体词**（`轨道交通` 的父词是 `地铁`），
这样命中台账里能看出「同一件事的几种说法」。

## 三、排除词：课件的坑在我们这儿是真的

课件举例「非本地同名地名」。我们这儿最像的例子就是 **「宁波」** ——
宁波三字的同名地点遍布全国，若按单词建排除词会大面积误伤。
**所以排除词要按词组建**（`宁波 + 外省地名`），而不是按单词。

我们这份样例**故意没有**把「外地」放进排除词：

- 「外地」在真库里的量不小，但语义是**两可的** ——
  「外地车占道」「外地来的民工投诉」都是**正当诉求**，
  拿它做排除词会把真诉求扣掉，属于**宁可漏，不可错杀**的取舍。
- 真正该扣的是**与民生诉求无关**的噪声：广告、招聘、转载。

> ⚠ 排除词是**减**的：多一个排除词，就少一批样本。
> 加排除词前必须确认「这个词出现，就一定是噪声」。

## 四、怎么用

1. **灌词表**：`python _tools/load_sample_keywords.py`（`--dry` 只看不写，`--scan` 灌完顺手扫描）
2. **系统里改**：界面「词表」页签 → 加词 / 停用 / 删除 → 点「扫描全库」
   （扫描是**后台任务**，要过全库楼层正文，页面不会卡）
3. **看命中**：词表页签点某个词的「命中」→ 看命中了哪些帖、分页翻
4. **落到交付物**：导出 CSV 时多一列「**词表命中**」，写这个样本命中了哪些词

**接口**（都在 `/api/keywords*`，写操作**仅管理员**，成员只读）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/keywords` | 词表 + 命中统计 |
| POST | `/api/keywords` | 加词（同词重复加 = 更新词类） |
| POST | `/api/keywords/{id}/enabled` | 启用 / 停用 |
| DELETE | `/api/keywords/{id}` | 删词（连命中记录一起删） |
| POST | `/api/keywords/scan` | 后台扫描全库 |
| GET | `/api/keywords/{id}/hits` | 某词命中的帖子（分页） |

## 五、已知局限

- **扫描是全量扫**：一次全表扫描 + 多词判定，实测真库 56 万层约 4 秒；
  但**词表越大越慢**（每层对每个词做一次子串统计）—— 词表上百个词时会明显变慢，
  届时应改为「按词建倒排」而不是每次全扫。
- **命中是子串匹配，不是分词**：搜「公交」会命中「公交化」这种误命中；
  词表用来**圈定范围**（哪些帖值得人看），**不能当精确检索用**。
- **扫描结果是快照**：改完词表要重新扫描才会更新命中；界面上的命中数是**上次扫描**的结果。
- **「词表命中」列随导出走**：命中台账为空时该列为空 —— 这不代表样本没价值，
  只代表它没命中当前词表（词表是研究设计，不是穷尽判据）。
