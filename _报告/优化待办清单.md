## 本轮开工范围（用户 2026-11-05 拍板：先做 P0）

### P0-1 修楼层发帖时间正则 —— 恢复 86.1% 楼层的发帖时间

- [x] **改 `程序/msyt/parsers.py` 的时间正则**（站方日期不补零 → 正则要求两位 → 匹配失败）
- [x] **补闸** `_tools/test_post_time.py`：真实写法全覆盖 + 补零归一化 + **真反向验证**
- [x] **存量回填工具** `_tools/backfill_post_time.py`：只抓详情页、只补 `post_time`/`post_ts`，不碰正文
- [~] **跑回填**（后台进程 pid 54020，断点续跑）

**验收判据**：新正则对 `2025-5-23` / `2026-9-2` / `2026-10-29` / 带秒 全部命中；
补零后输出格式与存量格式一致（`YYYY-MM-DD HH:MM`）；回填后全库空时间比例显著下降。

**实测结果**：
- 闸 `test_post_time.py` **25 项全绿**（含反向验证：旧正则在 6 个真实写法上失效 5 个）
- 小批量实测（500 帖 / 516 页）：**补 1,792 条时间，错误 0，4.2 分钟**（2.05 页/秒）
- 公式修正后的三个帖：`8236013 0/41→41/41`、`8294530 0/34→34/34`、`8333204 3/34→34/34`
- 存量格式已核对：`post_time` 全部 77,933 条**长度 16**（零补零、无秒）→ 新输出与之一致
- 全量后台回填：剩 **169,195 页**，约 **23 小时**（并发 2 路，给正常采集留余量）
  - 进度文件 `_备份/post_time_backfill.done`；日志 `_备份/post_time_backfill.log`
  - 停止：`Stop-Process -Id (Get-Content _备份\post_time_backfill.pid)`

⚠ **回填工具踩过的三个坑（都已修，闸里也记了）**：
1. 进度文件**提前标记**（在抓到之前就记「已完成」）→ 中途被 kill 会永久跳过 → 改成**先提交、后记进度**
2. worker 用 `q.get_nowait()`，队列空就 `return` → **worker 在主线程入队前就退出**，一页没翻 → 改成阻塞等
3. worker 里直接用主线程的 sqlite 连接 → 违反「连接不能跨线程」→ 改成 worker 只抓网络、**写库回主线程**

### P0-3a 抽取式摘要（只做抽取式，AI 版不做）

- [x] **本地规则生成摘要**：正文前 N 句 + 部门/类别/受理状态 + 楼层数/字数锚点
- [x] **可复现**：同一份数据两次生成**完全一致**（导出连导两次字节级一致）
- [x] **补闸** `_tools/test_summarize.py`

> ★ AI 摘要**本轮不做**：AI 结果不可复现（换模型就变），与「结论可追溯」冲突；
> 真要 AI，只能当阅读辅助，且必须标注模型与生成时间。

**验收判据**：同输入两次结果一致；摘要长度有上限；不引入新依赖；**不编内容**。

**实测结果**：闸 **全绿**。两个真问题在闸里暴露并已修：
- 空正文时**把标题拼进摘要**了 → 违反「不编内容」→ 改为只写「（无文字正文）」
- 纯图片帖同上处理，如实说明

### P0-2 导出 CSV 补 5 列

- [x] `发现时间` —— 该帖首次被发现的时间（`posts.fetched_at` 取 min，按 tid 聚合）
- [x] `原文摘要` —— 来自 P0-3a
- [x] `核验结论` —— 来自 P0-4（`verdict｜reason`）
- [x] `候选池路径` —— `thread_sources.source` + `thread_list_forms.kind`
- [x] `系统诊断` —— 现有的 `detail_warn`（以前**根本没导出**）
- [x] **补闸** `_tools/test_export_columns.py`：跑的是真代码 `DB.export_csv()`

**验收判据**：导出列数 23 → 28；旧 23 列内容与之前逐列一致（除新增）。

**实测结果**：闸 **全绿**。导出逻辑从 webapp 挪到 `DB.export_csv()`（闸才能跑真代码，不是跑自己的副本）。
- 旧 23 列**顺序与内容一字未改**（`_warn` 只是搬运 detail_warn，不进表头）
- 5 个聚合查询**一次拿到**（不给每行加子查询 —— 那是 60 万行 × 5 个子查询）
- 每帖楼主正文用窗口函数一次扫描取完（实测 188,492 行 / 2.8 秒）

⚠ **发现一处原有瑕疵（本次不改，记此备查）**：`full_text` 里楼层之间的分隔符是
**字面两个字符 `\n`**（SQLite 不解析字符串里的转义），不是真换行 → Excel 里会显示成 `\n`。
**不改**是因为改了旧列内容就变了；需要时另开一条。

## 全局纪律（每项都要守）

1. **改完必须跑闸**，闸要有**真反向验证**（改坏实现后同一批断言必须报红）。
2. **文档不钉死会自己变的数** —— 报告里的数字要么标「快照时点」，要么指向随包生成物。
3. **删除只走系统回收站**（`_tools/recycle_bin.py`）。
4. **存量写库前先备份**（`_备份/`），且**先试跑后写库**。
5. 报告改动后 **docx 必须回读验收**（md 与 docx 中文字符数必须相等）。
6. 发布前跑 `_verify_release2.py`，必须「干净」。
