msyt —— 民生e点通「群众留言板」
舆情采集与协作分析

面向中国宁波网「民生e点通 · 天一论坛」群众留言板（fid=1176）的只读采集器。 列表与详情双链路落库，本地 Web 界面做检索、完整性体检与导出；可选的多机协作让成员各自采集、回传并入权威库。

PythonSQLite + FTS5 FastAPI只读 GET 多机协作

它解决什么问题

双链路，分开计价列表 1 次请求拿元数据；详情 N×2 次请求拿楼层正文与受理时间线。
完整性有硬判据头楼、尾楼、页数与正文缺一不可；软警告单列，不与漏采混为一谈。
增量分两级新帖按 tid 去重；老帖靠回复数变大识别「站方追加了回复」。
可追溯每条记录保留 url 与 tid，任何结论都能回源复核。

三条踩出来的规矩

  1. 取 token 与用 token 之间不得插入 sleep 或重试。正文由异步接口注入，token 时效不足 30 秒。
  2. tid 不参与内容选择，token 才是钥匙。用错 tid 服务端仍返回同一正文且不报错——必须用响应自带的 pid 锚点做集合校验。
  3. 页码不能当水位。列表随时间漂移，增量要按 tid 与回复数签名判断。

界面里有什么

  • 总览：类别、受理状态、部门分组、时效灯、区县市分布，以及「结论边界」卡。
  • 检索与浏览：FTS5 + trigram，任意标签轴切片；详情抽屉含舆情卡片。
  • 采集与协作：一键增量、任务发布、成员领活与回传。
  • 完整性体检：硬问题 / 软警告 / 已识别的增量分列，可批量重跑或清除。
  • 标注台：批次视图、领活、快捷键流、人工与规则一致性反馈。

多机协作

站方不给 CORS 头，浏览器里采不到正文；正文必须由运行在采集者自己电脑上的 agent 发请求， 站方看到的是分散的普通用户，而不是一台服务器在集中爬。成员端不需要装这个包： 网站实时生成启动包，包里没有密码，只有一张绑定账号的限时票据。

公网入口按你的部署而定；文档与示例统一用 msyt.example.com 占位，仓库里不含真实地址。
