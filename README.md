# msyt —— 民生e网通「群众留言板」舆情采集与协作分析

> 课程作业 **02 民生e网通** · 独立项目 · **公开仓库**
> 目标站点：中国宁波网 民生e点通 · 天一论坛 › **群众留言板**（`fid=1176`）
> 目标地址：`https://bbs.cnnb.com.cn/forum.php?mod=forumdisplay&fid=1176`

一套**只读**的地方论坛舆情采集器：列表 + 详情双链路落库，本地 Web 界面做检索、完整性体检与导出，
可选开启多机协作采集（成员端 agent 在**自己电脑**上采、回传并入权威库）。

**只读**：不注册账号、不做短信认证、不发任何写操作（不发帖／不回复／不点赞／不收藏）。

## 一、三十秒跑起来

```powershell
cd 程序
pip install -e .              # 依赖：requests、beautifulsoup4
python -m msyt doctor        # 探站方 API（不写库）
python -m msyt taxonomy      # 抓分类体系（部门目录 / 区县市）
python -m msyt list --sources global --pages 5
python -m msyt detail --limit 50
python -m msyt web           # → http://127.0.0.1:8765/
```

Windows 上也可以直接双击薄壳（**手动启停，不注册开机自启**）：

| 文件 | 作用 |
|---|---|
| `程序/启动-web.cmd` | 起服务 + 自动开浏览器 |
| `程序/停止-web.cmd` | 按 PID 文件停服务 |
| `程序/web-status.cmd` | 看状态（PID / 端口 / 帖数 / 楼层数） |

底层是 `程序/web.ps1`（start / stop / status / restart），**默认只监听 `127.0.0.1`**。

## 三、读代码前先知道这三条（都是踩出来的）

1. **取 token 与用 token 之间不得插入任何 `sleep` 或重试。** 正文由
   `ajax_getpost.php` 异步注入，token 时效不足 30 秒。限速要加在「帖与帖之间」。

2. **`tid` 参数不参与内容选择，token 才是内容的唯一钥匙。**
   用 A 帖的 token 配 B 帖的 tid（甚至不存在的 tid），服务端会返回 **A 帖的正文**，
   而且 `code=1` **不报错**。舆情场景下这意味着「A 部门的回复被算到 B 部门头上」，
   结论失真且毫无察觉。**防御：用同一次响应里自带的 pid 锚点做集合校验，不匹配即判失败。**
   宁可少收，不可收错。

3. **增量要分两级**：帖级（新帖，按 `tid` 去重 + 日期早停）＋ 回复级（老帖新回复，
   靠 `reply_count|last_reply_at` 签名比对）。页码会漂移，**不能拿「上次到第 N 页」当水位**。

更完整的论证与实测证据见 [`_报告/方案报告.md`](_报告/方案报告.md)。

## 四、它长什么样（功能地图）

| 链路 | 命令 | 产出 |
|---|---|---|
| **列表采集** | `msyt list --sources …` | 帖级元数据 + 多维标签（类别 / 受理状态 / 部门 / 区县市 / 留言箱 / 时效灯） |

**采集日志**。

## 六、多机协作（可选）

站内不给 CORS 头，浏览器里**采不到正文**；所以正文采集必须由**运行在采集者自己电脑上的
agent** 发请求 —— 站方看到的是分散的普通用户，而不是一台服务器在集中爬。

```
控制面（管理员机器）                    成员设备
────────────────────                   ────────
发布协助请求 → 任务池
成员领活 → 领到具体 tid
   └→ 本机采集（内存 SQLite，**不落盘**）
        └→ 回传 → 并入权威库（走同一套完整性判据）
```

成员端不需要装这个包：网站**实时生成**一个启动包（`GET /api/agent/bundle.zip`），
包里没有密码、只有一张限时票据，成员只需填自己的邮箱密码。

- 成员端 agent 参数刻意比本机宽松（超时 / 重试 / 失联阈值），公网链路多好几跳。
- 回传失败会**重试**，不是一次失败就断链。
- 成员机器上的 agent 用**内存 SQLite**，整条链路不写任何磁盘文件。

细节见 [`_报告/分布式抓取协作方案.md`](_报告/分布式抓取协作方案.md)。

### 权限：界面层 + 接口层两道都做

| 层 | 做什么 |
|---|---|
| 界面层 | 非管理员看不到管理页签（采集作业 / 完整性体检 / 成员管理） |
| 接口层 | 管理类端点一律 `require_admin`，手动构造请求也只得到 403 |

**缺一道等于没锁**：只藏界面 → 改 URL 就能调；只锁接口 → 界面还误导人。

## 九、已知局限

| 项 | 说明 |
|---|---|
| 历史深度 | 论坛分页硬顶 500 页，实测越过即回绕 → 前台可见历史有下限，更早的数据是「前台不可达」，不等于「信息不存在」。可用 `filter=dateline` 时间窗再往深取。 |
| 站方会藏老帖 | 站方对部分历史帖只返回 Discuz「提示信息」页（正文仅作者本人可见）。程序把它记成独立的「站方限制」状态：**标记 + 写入正文 + 不计入已采详情帖**。这是数据现实，不是漏采 bug。 |
| 分页漂移 | 列表按时间倒序而站方是活的，新帖与被顶起的老帖会把分页窗口整体后移。程序有三道防线：页边界连续性检测、源采完回扫前 2 页、`tid` 幂等入库。 |
| 站方计数不自洽 | 列表页「回复数 + 1」常与实际楼层数差 1 —— 这是站方自己的问题，既不算漏采也不算增量，体检页单列为软警告。 |
| 其他版块 | 主体逻辑按 `fid=1176` 验证；同站其他版块预期可套用同一套采集器。 |
| 站内搜索 | 能否翻出 500 页之外的旧帖未验证（Discuz 搜索常需登录）。 |
