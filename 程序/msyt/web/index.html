⚠ 开始采集前，先在你自己的电脑上启动 Agent

采集必须发生在你自己的电脑上，不是在这台服务器上。
  • 站方不提供 CORS —— 浏览器出于安全，不允许网页直接跨站抓站方， 所以「开始采集」这个按钮在你的浏览器里采不到任何东西。
  • 如果采集跑在服务器上，站方看到的流量全来自管理员那一个 IP， 协作采集也就失去了「站方看到分散的普通用户」的意义。
  • 本机 Agent 启动后，网页才能把它叫醒；采到的内容会直接回传到这台服务器。
正在探测本机 Agent…
  1. 点下面的「下载成员端启动包」，解压到你自己电脑上。
  2. 双击包里的 启动助手.cmd —— 它会在你本机开一个 127.0.0.1:8766 的小助手 （浏览器出于安全不会让网页随便访问你电脑上的其它端口，所以要这个「双方都同意」的小助手）。
  3. 回到这个网页，点 「启动本机 agent」，输入邮箱和密码。
  4. 本机 Agent 变成「运行中」之后，再回来点「开始采集」。

成员端工具（在你自己的电脑上跑）

你的电脑上没有装 msyt 这个包，所以直接敲 python -m msyt agent … 只会报 No module named msyt。解决办法：从这个网页下载启动包 —— 包里已经写好了控制面地址（跟着你此刻访问的网址走，是动态的）， 解压后双击 启动采集.cmd，装完依赖后只问你要邮箱和密码就能开跑。

「启动本机 agent」需要你先双击启动包里的 启动助手.cmd： 它会在本机开一个 127.0.0.1:8766 的小助手，网页才能呼叫它 （浏览器出于安全不会让网页随便访问你电脑上的其它端口，所以要这个「双方都同意」的小助手）。
★ 端口被占用或被公司电脑封了？改上面的端口就行： 本机改这里，包里改 helper-port.txt（或在网页上「设为服务器默认」后重新下载一次包）—— 两边要一样，网页才叫得到助手。

协作采集（Beta）· 成员协助正文采集

管理员发布协助请求（选部门 → 自动挑出还没采详情的帖），成员用 本地 agent 领活、在自己机器上采正文、回传，管理员的权威库自动合并。 双方都能在这里看到同一条实时日志（带任务编号）。

★ 合并规则：不跳过，采取并覆盖 —— 成员回传的楼层里，同一帖同一楼层（pid）用成员版覆盖本地版； 成员多采到的楼层（站方追加的回复 = 增量）直接加进来； 本地有、成员没采到的楼层保留（不因成员少采而丢数据）。 每次覆盖与新增都进合并记录表，可查。

★ 成员端的承诺：agent 用内存 SQLite采集，全程不写任何磁盘文件， 回传成功即释放 —— 站方看到的是多个分散的普通用户，不是一个服务器在集中爬。

★ 与服务器失联 → agent 自动停止（心跳断了就不再领活、不再采， 采到一半的帖也不会回传半截数据）。

详情完整性体检

硬判据：缺头（楼主楼）/ 缺尾（末楼）/ 页数不足 / 正文为空 → 判为问题。 软警告：楼层号缺口、站方回复计数与实收楼层不自洽（站方自己的计数问题，不算我们漏采）。

已识别的增量：站方的「回复数」比我们上次采集时变大了 → 站方又回复了，本地那份正文过时了（已自动标记「待重采」并丢回队列）。 勾选后点「重跑所选」重新采一遍，新楼层会自动合并进来。

⚠ 注意与下面的软警告区分：「站方称 N+1 楼、本地实收 N 楼」 是站方自己的计数不自洽（常见，差 1），既不算我们漏采，也不算增量。

「重跑」= 数据留着，重新采一遍；「清除」= 彻底删掉，从零开始。
